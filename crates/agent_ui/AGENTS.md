# Chat and Ticks

- The Agent panel contains Chat and Ticks tabs. Ticks use pi-tick through `node ~/.pi/agent/tick/pi-tick.mjs` (`list --json`, `enable`, `disable`, `run --manual`, `kill`, `delete`, `show`). Running state comes from live PIDs in `active/*.json`.
- Run `cargo check -p agent_ui` from the repository root. Build the app with `cargo build -p zed`.
- For isolated tick checks, copy `~/.pi/agent/tick/*.mjs`, `commands/`, and `backends/` to a temporary directory. Create a disabled job with `pi-tick add` and launch Zed with `PI_TICK_DATA_DIR` set to that directory.
- Enable registers a real launchd agent (`dev.pi.tick.<id>`), even with isolated data. Do not enable jobs just to check navigation. If checking scheduling, delete the throwaway job afterward and remove any leftover `~/Library/LaunchAgents/dev.pi.tick.<id>.plist.disabled`.
- Remote ticks: `~/.pi/agent/tick/hosts.json` holds a JSON array of SSH aliases (currently `["devbox", "air"]`). Each host runs its own pi-tick and scheduler; Zed calls it over `ssh -o BatchMode=yes` with its own control socket `~/.ssh/zed-tick-%C` and `PermitLocalCommand=no`, then polls every 30 s. Remote Run Now detaches with `nohup` and returns after 3 s, so start-up errors still surface. Remote login shells are zsh: do not assign `status` in remote scripts.
- Create and edit use the Ticks `+` button and the detail `Edit…` button. pi-tick has no edit command, so `pi_tick::save` runs a Node script on the tick's host that imports pi-tick's own modules (`createTick`, catalog lock, validation, backend unregister and `cmdEnableInternal`). Edit keeps run history; editing is blocked during a run because re-registering would stop it. If pi-tick changes those module exports, save fails with the import error.
- To check create, edit, and delete on a remote host, create an enabled weekly tick there for a time that will not fire soon, check its crontab or launchd entry after each step, and delete it from the UI.
- To check remote ticks in isolation, put `hosts.json` in the temporary `PI_TICK_DATA_DIR`. Remote hosts still use their real data, so only use list, detail, and transcript views there. An unknown alias in `hosts.json` checks the unreachable-host row.
- Tick transcripts open in read-only editor tabs. Switching between Chat and Ticks keeps the current conversation and selected tick.
- Import external conversations from the sidebar's clock button, then the Import Threads button beside the history count. Select only the requested agent; agents with available sessions are selected by default. Imports go into the archive and skip existing session IDs.
- Large Pi imports can take many minutes: pi-acp scans the session files again for each 50-session page. Wait until the Pi row shows a count before importing. Verify completion by comparing Pi header IDs with `sidebar_threads.session_id` in the active channel's database; the success toast appears before all asynchronous saves necessarily finish.
- Kris Zed is installed at `/Applications/Kris Zed.app`. Build its binaries with `ZED_BUNDLE=true cargo build -p zed -p cli --features util/debug-embed`. Keep the existing bundle resources and entitlements, back up replaced binaries outside the bundle, then ad-hoc sign and verify the app. Restart through Quit Zed, not a forced process kill. A `ZED_BUNDLE=true cargo build --release -p zed` binary also installs this way. When a build runs detached from a tool sandbox, set `TMPDIR=/tmp`; the sandbox temporary directory is deleted when the tool call ends, and linking then fails with `clang: error: unable to make temporary file`.
